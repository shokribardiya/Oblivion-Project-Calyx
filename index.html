CALYX

CALYX connects three related projects, Angra, Nythos and Nythos Plus, around one aim: AI models that work together in workflows people can see, review and control.

Explore the systemsGet Angra on GitHub

Purpose and approach

Models are more useful when they can divide the work.

A single model turns a prompt into a response. Specialized models can instead take different roles, such as research, code or review, and pass structured results to one another.

The emphasis is coordination, specialization, interoperability and networking, with humans keeping direction and final control. The goal is workflows whose operation is visible and whose outputs can be reviewed. CALYX does not claim autonomous security auditing, vulnerability discovery or automatic code repair.

Security principles · designed for is not implemented

Designed for

  • Authenticated nodes and explicit peer trust
  • Encrypted transport when configured
  • Scoped permissions and task authorization
  • Least privilege, rate limiting, message validation
  • Replay protection where implemented
  • Fail-closed behavior and auditability

Not claimed as implemented.

Implemented in 1.0.0

  • Local operation; no server started and no network traffic sent by either script
  • Only models you authorize or have already loaded
  • Timeouts, cooldowns and output limits
  • Local logging

Networked model collaboration is not part of 1.0.0.

Optional deployment controls

  • Operator-controlled connectivity
  • Network segmentation and firewall rules
  • Secure transport chosen by the deployer

No claim of complete security is made.

Development log

SEP 2026 · ProductANGRA 1.0.0

ANGRA is an Oblivion-built integration layer for compatible models running through LM Studio and Bionic. It contains no models and replaces neither environment.

Version 1.0.0 ships as two Python scripts, one for LM Studio and one for Bionic, downloadable from this site.

Multi-node networking is designed but not part of 1.0.0.

— · ResearchFrom isolated models to a connected workforce

Different models can be given different roles such as research, code or review. ANGRA is the coordination layer for tasks, handoffs and verification.

“AI employees” is a metaphor for specialized model instances, not people.

— · SecurityDesigned for, implemented, optional

Networked collaboration needs authenticated nodes, encrypted transport, explicit trust, scoped permissions and auditability.

This site separates what is designed, what 1.0.0 implements, and what deployers must add. It makes no claim of complete security.

FAQ

Factual answers.

No public email address is configured for this site. Questions can go through the Angra repository on GitHub.

What is ANGRA?

An Oblivion-built integration and orchestration layer for compatible AI models running through LM Studio and Bionic.

Is ANGRA an AI model?

No. It is a coordination layer. The models come from the connected environments.

What does ANGRA connect?

Compatible runtimes and workflows exposed through supported LM Studio and Bionic environments.

Why connect multiple models?

Different models can take different roles, enabling specialization, parallel work and handoffs.

Can models communicate?

ANGRA is designed to coordinate structured communication between workers over configured connections. Version 1.0.0 does not send network traffic.

Does this require the internet?

No. Topology depends on deployment; local use needs no network.

Does ANGRA replace LM Studio or Bionic?

No. Both remain separate applications that you install yourself.

Is ANGRA an official LM Studio or Bionic product?

No. It is an Oblivion project designed to integrate with compatible environments, with no affiliation or endorsement implied.

Are the visualizations real?

No. They are labelled CONCEPTUAL or SIMULATED. LIVE is used only when a real runtime is connected.

Are the 100 AI workers running?

No. 100 AI workers is an organizational model, not live runtime data.
